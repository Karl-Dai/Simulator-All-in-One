# `SAIO` 统一配置存储方案

**Status:** Implemented; native GUI acceptance limits recorded

日期：2026-11-10

范围：`SAIO` 启动器及八个套件内模拟器。依据当前 `main` 的配置保存和 `portable` 启动逻辑整理。用户于 2026-11-11 明确要求修改程序。实现沿用现有用户数据目录，避免移动旧配置；其余推荐细节在代码验证中核对。

## 目标与当前差异

用户要求所有模块统一配置存储、自动保存和恢复，并替换体积较大的 JSON 存储。

当前启动器保存 `launcher.json`；IEC104 两端自动保存 JSON 工作区；Modbus 两端依赖手动工程文件；`OPC UA` 客户端自动保存工程，服务端依赖手动保存；`PMU` 主站把表单写入 `WebView` 本地存储，子站依赖手动预设。套件内子程序是独立进程，`Go` 与 `Rust` 两种后端同时存在。

完成后，启动器和八个模拟器采用同一套 `SQLite` 格式（内嵌数据库文件）、版本迁移协议和保存反馈。配置修改自动写入，重新打开程序恢复配置，用户无需为防止配置丢失而反复点击保存。

## 方案比较

| 方案 | 体积和更新方式 | 迁移与维护 | 结论 |
| --- | --- | --- | --- |
| `SQLite`，按对象和字段存储 | 按记录修改，避免反复存储字段名；小配置仍有数据库页开销 | 可使用事务、索引和明确版本；两种后端都可接入 | 推荐 |
| `MessagePack` 或 `CBOR` 二进制编码的整体文件 | 比文本紧凑，但修改一点通常仍需重写整个文件 | 需自行实现并发、文件替换和迁移恢复 | 不作为统一主存储 |
| 压缩 JSON 文件 | 可减小重复内容的磁盘占用，写入仍需要序列化整体文档 | 仍保留当前模块间不同保存规则 | 不符合本次统一目标 |

`SQLite` 事务和同机多进程访问的依据见官方文档：

- https://www.sqlite.org/isolation.html
- https://www.sqlite.org/wal.html
- https://www.sqlite.org/backup.html

已采用真实存储引擎测量。10,000 点时，`SQLite` 为 679,936 字节，紧凑 JSON 为 884,700 字节；100,000 点时，分别为 6,881,280 字节和 9,146,702 字节，减少约 25%。小配置存在固定页开销。完整数据与复现命令见 [`storage/VALIDATION.md`](../../storage/VALIDATION.md)。之前专用点表的合成测试未用于最终体积结论。

## 统一存储约定

### 数据位置

本次沿用现有用户目录。`Windows` 为 `%APPDATA%\SimLab`，`macOS` 和 Linux 沿用当前套件数据根目录。用户没有选择随 `EXE` 携带数据，保持现有路径。

以下设计以“选定的数据根目录”表述。原有二进制解压缓存继续独立放置，更新或修复缓存不能删除配置数据库。

### 一个数据库与明确的模块归属

选定根目录下使用一个 `saio.db`。启动器和八个模块共享格式，以固定角色标识区分配置归属。一个角色的保存、导入、清空只能修改自己的数据。多实例修改同一工作区时必须检查修订号，不能用旧页面状态覆盖较新的修改。

各程序直接访问同机数据库，不增加必须常驻的数据库服务器。`Go` 与 `Rust` 使用同一份 SQL 建表和迁移文件，并通过共同的文件样例检查互读结果。具体驱动版本在实现时核对当前锁定工具链后固定，不能引入需要 `Windows` `Go` 开启 `CGO` 的隐含要求。

采用短事务、外键约束、有限等待和可报告的锁冲突。`SQLite` 的 `WAL` 模式（先写事务日志再合并数据）允许读写并行，但同一时间仍只有一个写入者；它不适合多个计算机直接共享网络文件路径。对于不支持该模式的目标存储，应提示使用本地目录，不能关闭事务保护来绕过问题。

### 数据结构

公共表负责数据库版本、角色、文档、字段名称和修订号。连接、设备、点定义和订阅使用带类型的树状记录。每个容器的直接标量字段采用紧凑二进制记录，嵌套对象保留独立节点。`Go` 与 `Rust` 读取相同格式，共享 SQL 是结构定义的唯一来源。

禁止把现有完整 JSON 字符串改放进数据库一个字段，也不把 JSON 压缩后作为主要工作区记录。大点表变更应只更新相关记录。批量新增、批量删除、工程导入和工作区替换必须在事务中完成。

各类配置的保存范围：

| 对象 | 统一后的保存内容 |
| --- | --- |
| 启动器 | 主题、语言、收藏、最近使用 |
| IEC104 主站 | 连接、公共地址、协议参数、TLS/代理配置、控制表单参数 |
| IEC104 子站 | 服务、站、点定义、控制选项、仿真和协议参数 |
| Modbus 主站 | 连接、采集组、点定义、请求和重连配置 |
| Modbus 从站 | 连接、设备、点定义、初始值及仿真配置 |
| `OPC UA` 客户端 | 连接、安全选项、订阅节点、分组、采样与过滤配置 |
| `OPC UA` 服务端 | 服务配置、目录、节点定义、初始值及仿真配置 |
| `PMU` 主站 | 连接表单和可编辑采集参数 |
| `PMU` 子站 | 站配置、通道定义、仿真参数和命名预设 |

语言、主题和布局等用户选择也需统一通过后端保存，不能继续形成第二份配置来源。证书、密钥、CSV 回放文件等外部资源保留文件引用和既有安全边界；数据库格式本身不提供加密。

持续采集值、通信日志、图表历史和正在运行的连接状态不纳入配置自动保存。主站实时点快照继续按用户显式导出处理，不能将每次采样都写进配置库。恢复配置后保持连接和服务停止，用户点击后才连接或监听。

## 保存、恢复和手动工程操作

- 创建、编辑、删除和批量修改配置统一触发后端事务保存。明确的提交操作成功时，应已完成配置持久化。
- 连续表单输入允许约 300 毫秒 合并写入。界面提供保存中、已保存、保存失败状态；关闭窗口前处理尚未完成的配置写入。
- 错误不能只写日志或被静默忽略。磁盘已满、目录只读、锁等待超时均显示失败，并保留用户修改以便重试。
- 后端负责保存顺序与事务；前端不直接操作数据库。
- 启动恢复必须在首次工作区读取前完成，防止空页面覆盖已有配置。
- 手动“保存/另存为”用于独立工程副本和迁移到另一台电脑，不再承担日常防丢失职责。
- 新工程副本统一采用 `.saioproj`，内容为 `SQLite` 工程数据库。导出只包含所选工作区和角色，接收模块核对角色和格式版本后导入。
- 保留旧 JSON、`.modbusproj`、`.opcuaproj` 等工程导入能力；新配置默认不再输出旧 JSON 格式。

## 旧配置迁移

首次升级按角色分别迁移现有自动保存文件、预设和界面本地存储。迁移记录包括来源标识、内容摘要、状态及目标结构版本，以保证重复启动不重复导入，也不覆盖数据库中的新修改。

`WebView` 本地存储由原有界面读取，再通过受控后端迁移接口提交；不直接解析其他浏览器的内部数据库。没有自动保存过的 Modbus 和 `OPC UA` 服务端工程，不能凭空找回，用户可手动导入原工程文件。

迁移前保留原文件，事务提交并验证成功后才记录完成。失败时撤销本次数据库变更并报告来源，原文件继续保留。旧数据无法读取时不能创建空工作区并假装迁移成功。

已有数据库使用明确的递增结构版本。后续结构升级须先备份，再在排他迁移事务中执行并更新版本；多个程序同时启动时只有一个执行迁移。遇到高于自身支持版本的数据库，拒绝写入并提示使用匹配版本，不能覆盖为旧格式。

运行中的旧版程序可能继续修改旧存储，升级前应先关闭旧模拟器窗口。此次设计不主动终止现场连接。

## 备份与故障处理

后续可在统一入口增加完整数据库备份和恢复。在线备份需通过 `SQLite` 备份接口生成一致副本，不能把运行中的主数据库文件单独复制作为备份。现有迁移保留旧配置原件。本次初始结构版本没有升级操作；未来结构升级需先增加备份和升级测试。

数据库损坏时保留原件，报告可恢复副本；禁止静默删除数据库并恢复空配置。导入工程或恢复备份须校验文件标识、结构版本和角色归属。

独立版上游应用不改变默认路径和文件格式。本次实现通过套件补丁和构建开关接入新存储，避免破坏独立版工程兼容性。

## 交付顺序与验收

一次设计覆盖统一格式，按可验证阶段实现；最终验收必须覆盖八个模块，不能以少数模块接入代替统一完成。

1. 建立共享 SQL 结构、迁移、备份和 `Go`/`Rust` 访问约定，完成跨语言兼容和并发测试。
2. 接入启动器、IEC104 和 `OPC UA` 客户端，迁移已有自动保存来源。
3. 接入 Modbus 两端、`OPC UA` 服务端和 `PMU` 两端，补齐缺失的自动保存与恢复。
4. 统一保存状态、工程副本导入导出、旧数据迁移提示。
5. 构建套件并执行 `Windows`/`macOS`/Linux 的相关验证。

必须验证的行为：

- 八个角色分别创建、编辑、删除配置后关闭重开，结果一致。
- 批量操作中途失败或进程中断，数据库只呈现操作前或完整提交后的状态。
- 两种后端、多个进程同时保存时，角色数据互不覆盖；同一工作区的陈旧写入被识别。
- 每一种旧格式迁移后数量和字段一致，重复启动不重复导入，原件与备份仍可恢复。
- 更新或移动 `portable` 程序后，配置位置符合用户选择；修复二进制缓存不修改数据库。
- 数万和十万点工程分别测量启动、单点修改、批量导入、关闭和磁盘占用，报告主数据库、事务日志及备份的独立大小。
- 磁盘已满、只读目录、锁超时、损坏数据和不支持的新格式均有可见错误，不静默丢失配置。
- 新工程副本可跨机器导入，旧工程继续可读，服务恢复后不会自动发起现场通信。
