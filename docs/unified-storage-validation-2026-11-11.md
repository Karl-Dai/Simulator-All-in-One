# 统一配置存储验证

日期：2026-11-11。源码基于 `main` 的 `9bfe1b3`，保留原有 Modbus `FC16` 类型写入和字节序功能。

## 已实现行为

- 启动器及八个套件角色共享 `saio.db`，按角色和文档隔离。`Go` 与 `Rust` 读取同一格式。
- 修改自动保存，重开恢复配置，连接和服务保持停止。持续采集值及日志不进入配置库。
- 原自动保存文件、界面设置、`PMU` 预设仅首次迁移，原件保留。旧工程导入继续使用原有格式转换。
- `.saioproj` 是只含选定角色及文档的单文件数据库，导出不能替换共享数据库或事务文件。
- 同一角色的陈旧写入返回冲突；保存失败保留或恢复原配置，恢复失败阻止默认值覆盖。
- 窗口关闭及退出通过原生通知等待配置写完，保存失败保留窗口及可修正的表单。

## 自动化验证

公共引擎已验证两种语言互读、64 位整数、空容器、Unicode、事务回退、并发初始化、陈旧写入、损坏数据、单文件导出和新数据库权限。实际格式体积及命令见 [`storage/VALIDATION.md`](../storage/VALIDATION.md)。十万点样本为 6,881,280 字节，紧凑 JSON 为 9,146,702 字节。

| 范围 | 验证内容 |
| --- | --- |
| 启动器 | 偏好迁移、冲突、无效配置阻止写入、前端测试和开发构建 |
| IEC104 主站 | 原子编辑、导入、失败后保留原运行对象、恢复后断开、界面测试 |
| IEC104 子站 | 配置修改、循环配置、旧格式迁移、跨服务回退隔离、实时值和任务保留 |
| Modbus 两端 | 自动保存和重开、旧版工程转换、未知版本拒绝、重复地址导入失败保留配置、无关连接隔离、并发检查 |
| `OPC UA` 两端 | 工作区保存和重开、导入导出、无效恢复阻止写入、失败回退、恢复后停止 |

根目录使用定向 `go test` 覆盖程序及 `internal`、存储、界面包。现有未跟踪文件 `output/playwright/modbus-fc16/acceptance-backend.go` 引用了其他项目的内部包，因此本机直接运行 `go test ./...` 会失败；该文件保留。打包脚本的 72 项测试通过，1 项按平台跳过。

本轮构建和测试日志保存在 `.validation/unified-storage-build/` 和 `.validation/unified-storage-close/`。`Windows` 已交叉编译纯 `Go` 存储测试程序和启动器；没有执行 `Windows` 或 Linux 原生窗口验收。

## 原生运行证据与限制

IEC104 主站使用独立测试应用标识和隔离的 `SIMLAB_DATA_DIR` 启动。真实界面与后端接口创建了 `ui` 文档；重启读取旧 `master_workspace.json`，生成 `workspace` 和迁移记录，保留公共地址 7、8 及原文件。测试进程已关闭。

桌面工具选择新测试窗口时返回 `cgWindowNotFound`。因此，本轮没有完成可见窗口点击、文件对话框及关闭操作的完整验收；构建、进程和数据库证据不代替这些验收。

## 验证失误及恢复

审查期间误把 `PMU` 应用程序当作测试程序执行，在默认用户目录新建了 `saio.db`、`saio.db-wal`、`saio.db-shm`。确认创建时间为本次启动，数据库仅含 `pmu.master/ui`；没有执行连接操作。原 `launcher.json`、旧预设及角色目录时间未变。

已停止该进程，保存原始三文件和一致数据库备份，再将本次新文件移出默认目录，恢复原先没有该数据库的状态。备份位于 `~/Library/Application Support/SAIO/Backups.noindex/20261111-accidental-pmu-validation/`，其中 `repair.json` 记录检查结果。该事件已告知用户。

本轮未提交、推送或安装新版本。
